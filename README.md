# Context Bridge v20

사용자 프로필에서 현재 질문에 필요한 정보만 서버 내부에서 선별하고, 사용자가 승인한 정보만 최종 생성 모델에 전달하는 React·Express·Supabase 프로젝트입니다.

## v20 보안 흐름

1. 질문 구조화: 원하는 결과, 현재 결정, 조건, 위험 영역, 시간 범위, 접근성·안전을 추출합니다.
2. 후보 검색: 어휘·형태 정규화·최근 맥락·관련 위험 영역을 결합합니다.
3. 무결성 검사: 오래된 정보, 질문과 프로필의 수치 충돌, 같은 제목 카드 간 모순을 표시합니다.
4. 사용자 승인: 일반 정보만 조건부 기본 선택하며 민감정보는 항상 선택 해제입니다.
5. 답변 생성: Proposal Snapshot에서 승인 ID를 재검증하고 승인된 값만 모델에 전달합니다.
6. 생성 후 검증: 거절 정보 누출, 필수 제약 누락, 질문 미응답, 개인정보 반복을 검사해 자동 수정합니다.
7. 기억 제안: 새 정보는 `PENDING` 후보로만 만들고 사용자가 `save`를 선택해야 저장합니다.

`confidential` 카드는 후보·승인·생성에서 차단됩니다. 거절 카드의 값·제목·ID·전체 Vault 크기는 생성 프롬프트와 감사 로그에 남기지 않습니다. 후보 shortlist는 최대 14개입니다.

임베딩 검색은 실제 벡터 저장소가 없는 상태에서 흉내 내지 않았습니다. 현재 의미 우회는 서버 내부의 한국어 형태·동의 표현 정규화로 처리합니다.

## 사용자 화면


# Context Bridge

> 사용자의 정보를 무조건 AI에 전달하는 것이 아니라, 질문에 필요한 맥락만 추천하고 사용자가 직접 승인한 정보만 활용하는 사용자 통제형 AI 서비스입니다.

## 1. 프로젝트 배경

일반적인 생성형 AI는 사용자의 상황과 제약을 충분히 알지 못해 매번 같은 설명을 반복하게 하거나, 반대로 너무 많은 개인정보를 한꺼번에 사용하게 만들 수 있습니다.

Context Bridge는 다음 문제를 해결하는 것을 목표로 합니다。

- 사용자가 자신의 정보를 매번 반복해서 설명해야 하는 문제
- 질문과 관련 없는 개인정보까지 AI에 전달될 수 있는 문제
- 고령층과 AI 초보자가 복잡한 설정을 이해하기 어려운 문제
- AI가 저장한 정보가 언제, 어떻게 사용되는지 알기 어려운 문제

## 2. 핵심 아이디어

질문이 입력되면 전체 사용자 정보를 그대로 보내지 않고 다음 흐름으로 처리합니다。

```text
사용자 질문
→ 질문 의도 및 결정 영역 분석
→ 관련 맥락 후보 추천
→ 민감도·최신성·충돌 검사
→ 사용자 승인 또는 거절
→ 승인된 맥락만 AI에 전달
→ 개인화 답변 생성
→ 새 정보 저장 여부를 다시 사용자에게 확인
```

## 3. 핵심 원칙

1. 사용자가 승인한 정보만 최종 생성 모델에 전달합니다。
2. 거절한 카드의 값, 제목, ID, 존재 여부를 프롬프트와 로그에 포함하지 않습니다。
3. 민감정보는 기본 선택 해제 상태로 제공하고 사용자가 직접 승인하도록 합니다。
4. 기밀정보는 모델에 전달되지 않도록 차단합니다。
5. 모든 제약을 무조건 적용하지 않고 현재 질문과 관련된 제약만 검사합니다。
6. 오래된 정보, 현재 질문과 프로필의 충돌, 카드 간 모순을 검사합니다。
7. 생성된 답변을 다시 검증해 개인정보 노출과 필수 제약 위반을 확인합니다。
8. 답변에서 발견된 새 정보는 자동 저장하지 않고 사용자 승인 후에만 저장합니다。
