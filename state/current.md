## 핵심 보장

- 클라이언트는 질문 분석 시 카드 목록을 보내지 않는다.
- 서버가 검증된 사용자 토큰으로 RLS가 적용된 계정 데이터만 읽는다.
- `persona_type`이 아니라 실제 카드 속성으로 질문별 맥락을 구성한다.
- 승인 전 외부 AI에 카드 값이 전달되지 않는다.
- 승인 Snapshot, 실제 사용 카드, 답변, 기억 후보가 계정별로 기록된다.
- RLS뿐 아니라 복합 외래키도 교차 소유자 참조를 차단한다.

## 현재 가장 큰 위험

실제 Supabase 프로젝트 자격 증명이 없는 환경이라 원격 migration·seed·로그인을
아직 실행하지 못했다. 로컬 인증 계약과 API 경계는 통과했지만, 발표 전 반드시
두 실제 계정으로 로그인해 행 격리와 라이브 Gemini 답변 차이를 확인해야 한다.

그 다음 위험은 생성 완료 시 Proposal/Snapshot/감사/기억 후보 기록이 단일 DB
트랜잭션이 아니라는 점과 서버 재시작 뒤 진행 중 Proposal을 복구하지 못한다는 점이다.
